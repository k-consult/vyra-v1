Applied Patterns — Already Correct

Named so they're recognized as load-bearing, not "refactored" away by someone who doesn't see the pattern.

Repository
api/modules/*/repo.ts
Every Cypher query isolated behind a repo function — callers never see a driver or session.
Gateway
lib/graph-db
The one translation boundary to Neo4j — nothing outside it holds a driver handle.
Singleton + Lazy Factory
DB.getInstance() + per-call-site db()
No module pays a connection cost until it actually queries.
Idempotent Receiver
MERGE-based CSV loads + agent writes
Re-running ./ingest.sh or re-polling a signal never duplicates a node.
Registry (partial)
agents/registry.ts
A named lookup of agent families — static today, graph-backed in the target design.
Known Debt
  • Edge + Repo collapsed — every api/modules/<domain>/index.ts route calls repo.ts directly; nothing validates input or sequences a domain rule between them. Node-spine's own edge → core → repo spine is two layers here, not three.
  • Errors silently become empty results — 34 of 41 catch blocks across repo.ts files log and return []. A connection failure and "genuinely zero rows" are indistinguishable to every caller, including the UI.
  • One Gateway, two names per operation — lib/graph-db exposes fetch/fetch2 and exec/exec2 as identical pass-throughs. Call sites already voted: 71 use fetch2, zero call fetch directly.
